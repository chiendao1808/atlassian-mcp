# Confluence Server 6.1.2 / REST 6.1.4 — API Reference for Planning & Implementation

> **Runtime target:** Confluence Server **6.1.2**  
> **Primary documentation reference:** Confluence REST API **6.1.4** — latest patch of the 6.1.x line  
> **Compatibility boundary:** every implemented endpoint/parameter/status must remain compatible with **6.1.2**.

This reference is organized in the same implementation-oriented format as the existing Jira/Bitbucket API reference: endpoint groups are tables with exact method/path, params, body/headers, permission concept, success status, sample curl and sample response.

## 2. Base URI, authentication and common headers

### Base URI

```text
{CONF_BASE}/rest/api/{resource}
```

`CONF_BASE` may already include a context path:

```text
https://confluence.internal/confluence
```

Do **not** hard-code `/confluence`.

### Authentication

| Mechanism | Sample | Planning note |
| --- | --- | --- |
| Basic Auth | `curl -u "$CONF_USER:$CONF_PASSWORD" "$CONF_BASE/rest/api/user/current"` | Baseline for this 6.1.2-era Server integration. Use HTTPS. |
| MCP session auth proposal | `confluence_authenticate(username,password)` → validate with `GET /rest/api/user/current` | Project design, not an Atlassian requirement. Keep credentials in memory only. |
| PAT / Atlassian Account ID | Do not use as baseline | These are modern-version concepts and must not be imported into the 6.1.2 contract without proof. |

### Common headers

| Case | Header |
| --- | --- |
| JSON read | `Accept: application/json` |
| JSON write | `Accept: application/json`; `Content-Type: application/json` |
| Attachment multipart write | `Accept: application/json`; `X-Atlassian-Token: nocheck`; let HTTP client generate multipart boundary |
| Authentication | HTTP Basic `Authorization` generated by client / `curl -u` |

## 3. Expansion, pagination and errors

### Expansion

```text
?expand=space,body.storage,version
```

Nested expansion uses dot notation:

```text
body.storage
container.version
restrictions.user
```

Preserve `_links` and `_expandable` when returned.

### Pagination defaults

| API group | `start` | Default `limit` | Notes |
| --- | ---: | ---: | --- |
| Content / content search | 0 | 25 | Server may enforce a lower fixed limit |
| Child content / comments / descendants | 0 | 25 | Expansion can affect practical response size |
| Attachments | 0 | 50 | |
| Labels | 0 | 200 | |
| Content properties | 0 | 10 | |
| Restrictions by operation | 0 | 100 | |
| Groups / group members / user memberships | 0 | 200 | |
| Long tasks | 0 | 100 | |
| Generic search | 0 | 25 | |
| Spaces / space content | 0 | 25 | |
| Space properties | 0 | 10 | |
| Audit | 0 | 1000 | |

General response fields can include:

```json
{
  "results": [],
  "start": 0,
  "limit": 25,
  "size": 25,
  "_links": {
    "next": "..."
  }
}
```

Rules:

- Send explicit `limit` from MCP tools that expose pagination.
- Prefer `_links.next` when present.
- Do not assume every endpoint returns `totalSize`.
- Do not confuse server pagination/caps with MCP-side response truncation.

### Error mapping

| HTTP | Meaning in this API line | MCP note |
| ---: | --- | --- |
| 400 | Invalid query/body/version shape/CQL | Preserve safe upstream error |
| 403 | Authenticated but permission/function unavailable | Map to forbidden where unambiguous |
| 404 | Missing **or not visible** for many content/space endpoints | Prefer `NOT_FOUND_OR_NOT_VISIBLE` |
| 409 | Optimistic version conflict on documented versioned resources | No blind mutation retry |
| 413 | Content/space property value too long | Keep separate from attachment max-size behavior |
| 202 | Async operation accepted, notably space deletion | Not equivalent to completed deletion |
| 204 | Successful no-body operation / purge / delete depending endpoint | Do not expect JSON |

### Content update notes

| Vấn đề | Contract |
| --- | --- |
| Optimistic versioning | `version.number` phải là version mới; không blind retry mutation sau conflict/timeout. |
| Move page | Gửi `ancestors:[{"id":"<newParentId>"}]` cùng version mới. |
| Restore trash | Tăng version và set content `status=current`. |
| Draft | 6.1.x docs mô tả một số draft flows nhưng cũng ghi “Updating a draft is not currently supported”; không suy rộng. |
| Body format | Khi cần editable source, dùng `body.storage`. Không tự rewrite Confluence storage XHTML nếu tool không có contract transform riêng. |
| 404 | Có thể là missing hoặc not visible. |

### Attachment notes

| Topic | Rule |
| --- | --- |
| Multipart field | Must be named `file`. |
| XSRF header | Multipart writes require `X-Atlassian-Token: nocheck`. |
| Boundary | Do not manually set multipart `Content-Type`; let the HTTP client create the boundary. |
| Multiple files | Upstream create endpoint supports multiple files. MCP may intentionally restrict to one file/tool call for safety/observability; document it as an MCP restriction. |
| Retry | Never blind-retry upload/update after the request may have been transmitted. |
| Oversized file | Historical 6.1.x generated docs report it under 404 for create attachment; preserve upstream body/status and gate behavior on real 6.1.2. |

## 17. Compatibility notes for planning/implementation

| Topic | 6.1.x contract / note | Required action |
| --- | --- | --- |
| Documentation version | Use 6.1.4 as readable reference, but 6.1.2 is runtime truth. | Every accepted MCP endpoint remains bounded to 6.1.2. |
| Path prefix | Generated resource headings may display `/rest/content/...`; actual public API base is `/rest/api/...`. | Implement `/rest/api/...`. |
| Context path | Confluence may run under `/confluence` or another context. | Build paths relative to configured base URL. |
| Authentication | Basic Auth fits 6.1.2-era Server. | Do not import PAT/Account-ID assumptions from modern docs. |
| Pagination | `start`/`limit`; defaults differ by endpoint. | No global default; preserve server paging metadata. |
| Expansion | `expand` + nested dot notation. | Prefer passthrough for generic reads. |
| Content update | Requires new `version.number`. | Optimistic concurrency; no blind retry. |
| Property updates | Content/space properties use versioning; 409 is documented. | Preserve conflict semantics. |
| Attachment writes | Multipart + `X-Atlassian-Token: nocheck`; part `file`. | Mandatory contract tests. |
| Attachment max size | Historical create docs strangely list oversized attachment under 404. | Preserve upstream; stage-test. |
| Content delete | 200 trash, 204 purge. | Make permanent purge explicit/destructive. |
| Space delete | 202 + long task. | Never report immediately completed deletion. |
| 404 semantics | Often missing OR not visible. | Neutral error mapping. |
| Descendants | Only comment descendants are explicitly supported in docs. | Do not assume recursive pages. |
| Restrictions | Reviewed API is read-oriented. | Do not invent write tools. |
| Users/groups | Reviewed API is read-oriented. | Do not import modern admin REST. |
| Macro hash | Already deprecated in 6.1.x docs. | Prefer macro ID; defer hash tool. |
| CQL | Exact fields/functions are version-sensitive. | Raw CQL passthrough, 6.1.x compatibility only. |
| Mutation retries | Writes may have succeeded before timeout. | No blind POST/PUT/DELETE replay. |
| MCP truncation | Separate from server pagination/cap. | Report explicitly if MCP response is truncated. |

## 19. Contract-test checklist per endpoint

| Test class | Required checks |
| --- | --- |
| MCP schema | required fields, exactly-one constraints, enum values, read/write/destructive annotations |
| HTTP path | exact `/rest/api/...`; context path not hard-coded |
| Query | encoding, repeated params, defaults, pagination |
| JSON | exact body preservation; no field normalization not required by API |
| Multipart | `file` field, comments/minorEdit, XSRF header, client-generated boundary |
| Auth | Basic header/session behavior; credential never appears in log/response |
| Success | every documented success status, including 202/204 variants |
| Errors | 400, 403, ambiguous 404, 409, 413 where relevant |
| Versioning | stale version conflict; no blind retry |
| Pagination | start/limit, `_links.next`, final page, server smaller-than-requested limit |
| Truncation | server vs MCP truncation are distinguishable |
| Real host 6.1.2 | required for all `STAGING_REQUIRED` rows |

## 20. Mandatory staging gates before implementation freeze

| Gate | Why |
| --- | --- |
| `POST /rest/api/content` exact success status/headers | Generated 6.1.x operation text does not expose a numeric success status clearly |
| `GET /rest/api/user/current` auth edge cases | Validate actual 6.1.2 login/permission behavior |
| 403 vs 404 on target instance | Reverse proxy/security configuration may affect visible behavior |
| Oversized attachment upload | Historical docs map this unusually to 404 |
| CQL beyond minimal baseline | Avoid newer-version fields/functions |
| Audit endpoints | Body/status/permission documentation is incomplete |
| Blueprint publish | Body/status details are not strong enough for a generic MCP contract |
| Reverse proxy/context path | Confirm actual base URL behavior and redirects |

## Final implementation rule

Only implement a Confluence MCP operation when its contract is explicit enough to know:

```text
method
path
params
headers
body
success status
error behavior
permission behavior
pagination/cap
retry safety
response handling
```

If the 6.1.2/6.1.4 sources do not establish one of those points, mark the endpoint `STAGING_REQUIRED`; do not silently resolve the gap from a newer Confluence release.
